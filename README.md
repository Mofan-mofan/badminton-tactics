# 羽毛球单打战术助手

一个**单文件、零依赖**的羽毛球单打决策工具：告诉它「我站在哪、球落在我这里、球是什么球」，
它算出这一拍该打什么、打到哪里，并且把每一项打分的来路摊开给你看。

**在线试用**：<https://mofan-mofan.github.io/badminton-tactics/>（与本地文件同一份代码，无需安装）

也可以离线用：双击 `index.html` 就能打开。不需要 Node、不需要构建、不联网，所有档案存在本机
`localStorage` 里。

## 怎么用

1. 点「载入示例局面」——比对着空白表单填空快得多；
2. 局面卡片里 ④ 来球类型 / ⑤ 我的击球点高度 / ⑥ 到位程度 / ⑦ 体力，就是这一拍的全部输入；
3. 球场上三个点都能拖：① 我的位置（蓝）、② 来球落点（黄）、③ 对手位置（红）。
   想看空当怎么随站位变化，就把红点拖到对手实际站的位置——③ 卡片会立刻重算；
4. 展开任意一条推荐的「打分明细」，看这个分数是怎么来的。

## 它回答什么问题

业余打球时真正难的不是"不知道有哪些球可以打"，而是**同一拍里几个选择看起来都对**：
这个位置能杀，但杀完我自己空了；那个落点是空当，可我的手法不到位。

这个工具把这类纠结拆成可比较的数字，并且要求它**给出理由**：

```
#1  高远球 → 对方后场右   67/100
    「对方后场右」（距他 6.08m · 身后）对方几乎够不到，是明显的空当
    成功率约 94%（击球点高点 · 主动 · 你的后场技术 70）
    「对方后场右」是对方弱区（强度 0.9）
    跑动 2.23m 击球 + 2.23m 回位
    失误概率约 6%
    对方最可能：对方后场薄弱，只能回高远或过渡，你可以继续压
    成功率 94% · 失误 6% · 我耗 2.34 · 对方耗 2.22 · 跑动 4.47m
```

## 核心：把一拍球还原成几何

场地用米做世界坐标（`x: -2.59~+2.59`，`y: 0 我方底线 ~ 13.4 对方底线`），
半场切成 18 个分区（3 深度 × 3 宽度 × 2 方）。

**v0.2：对手站位可以拖了。** 直接拖动球场上的红色标记，站位同时驱动三件事：

1. **落点调动性打分** —— 对手够每个分区要多久，取决于他此刻站在哪；
2. **双方体力消耗差** —— 同一拍球，他离落点越远，这一拍就越累；
3. **独立的空当分析卡片** —— 9 个落点的距离 / 难度 / 弱点 / 综合价值排行。

站位有两种来源：默认**按来球类型推断**（他挑后场，他人就在后场），或者**手动拖到实际位置**。
手动时屏幕上会留一个灰色虚线圈标出"推断位置"，你可以看见自己猜得多离谱。
拖到不合常理的位置（比如他刚挑完底线你却把他放在网前），会给出提示而不是静默接受。

### 身后球单独建模

退后接球要先转体再倒步，同样的直线距离比前冲和侧向慢。所以：

- 落点比他更靠底线 ≥ 0.35 米才开始加步法代价，到 2 米长满（最高 1.30×）；
- ≥ 1 米才算真正的「身后球」并打标——没有门槛的话，对手一站网前，9 个区会全被标成身后，
  这个标记就没有信息量了；
- 臂展长的人能后仰伸手接球，满惩罚降到 1.16×。

## 打分模型

9 个因子加权，每项都单独展示（值 × 权重 = 贡献），没有黑箱：

| 因子 | 默认权重 | 含义 |
|---|---|---|
| `oppReach` | 1.60 | 落点调动性：对方够到这个点有多难受 |
| `exec` | 1.35 | 以你的手法，这一拍的成功率 |
| `weak` | 1.20 | 命中弱区 |
| `myCost` | 1.00 | 你自己跑动 + 回位的代价（负向） |
| `strong` | 0.90 | 避开强区（负向） |
| `attack` | 0.90 | 进攻连续性（打完这拍下一拍谁主动） |
| `risk` | 0.90 | 失误代价（负向） |
| `stamina` | 0.80 | 双方体力消耗差 |
| `rally` | 0.60 | 回合长短偏好 |

最终 `score = 50 + 45 × 加权原始值`，权重条可以现场拖。
**空当榜的「综合」列用的就是 `oppReach + weak + strong` 这三项、同一套权重**——所以调权重时
那张表会跟着重排，它也保证和主榜的第一名对得上（有一项自检专门守这件事）。

数据规模：26 种球路（7 大家族）· 8 种来球 · 5 种体型 · 14 个特征标签 · 5 个水平档 · 4 套示例档案。

## 特点

- **真·单文件**。HTML 里两个内联 `<script>`：纯逻辑引擎 + 界面层。引擎部分不摸 DOM，
  所以界面崩了引擎还能用。
- **引擎是 UMD 的**。`module.exports` 给 Node，`root.BadmintonEngine` 给浏览器——
  将来搬到小程序时，引擎一行不用改。
- **不假装精确**。参数是手工标定的经验值，界面上写的是"相对难度""约 94%"，
  不给虚假的小数位；体力差、成功率都注明是估计。
- **几何看得见的地方就画出来**。球路线、落点、触及圈、对手位置全在同一张 SVG 上，
  落点榜每一行可点击预览。
- **自带 12 项引擎自检**，不需要任何测试框架。
  打开 `index.html#selftest`，或点页面里的"跑一遍引擎自检"。
  守的是**静默失效**类问题：数值反了、NaN 渗进几何了、手动站位其实没生效——
  这些在界面上看不出来，但结果会全线错。
- **触摸可用**。拖拽走的是 Pointer Events 而不是鼠标事件，所以手指能直接拖；
  窄屏有两处断点（420 / 480）把双列收成单列。诚实说一句：**没在真机上验过**。

## 已知边界

- **只算单打、只算一拍。** 不做多拍推演，不考虑比分和关键分。
- **参数没有用真实比赛数据校准过。** 方向和相对量级是合理的，绝对数值不要当结论用。
- 强弱区是从体型 + 特征标签 + 水平**推导**的，不是从你的观察记录来的（可手动覆盖）。
- 球速、飞行时间没有建模，落点难度用的是"等效距离 / 覆盖速度"的简化模型。

## 改进方向

1. **两拍推演**：现在推荐的是单拍最优。真正该做的是"这拍打完，他大概率回哪，
   下下拍是什么"——引擎里已经预留了 `likelyReply()`，把它接进打分形成 2~3 层搜索。
2. **用录像校准参数**：`SPEED_SCALE`、`REACH_TIME_REF`、各因子的惩罚系数都是拍的。
   录 20 个回合，标出每拍的站位和落点，反推这几个常数，比再加十个功能有用。
3. **对手建模从"档案"升级到"这一场的观察"**：加一个逐拍记录面板，
   打的时候点几下，让弱区强度随实际回球分布更新，而不是开局就写死。
4. **训练模式**：给定一个局面，让你先猜该打什么再揭晓评分，把你的判断偏差统计出来——
   这才是这类工具对涨球最有用的部分。
5. **拆成模块 + 加真实测试**：目前是单文件优先（双击即用）。如果要做成小程序，
   把引擎抽成独立包、自检迁到 Node 测试、补上 CI，然后 UI 层按平台各写一份。
6. **工程细节**：渲染是字符串拼 HTML + 整块替换 `innerHTML`，档案上百时会变慢，可改成局部更新；
   `localStorage` 用单键存全部档案，没有版本号与迁移逻辑，字段改名会静默丢数据。

## 关于这份代码

写它一半是为了练手，所以有几处刻意的设计选择值得说明：

- 所有标定常量集中在一个 `CALIB` 导出里，而不是散在公式中——方便改，也方便被测试引用。
- 注释是中文的，且主要写**为什么这样算**和**不这样会怎样**，不写"这行在做什么"。
- 界面上的每个数字都能反查到公式；反查不到的那种"AI 感"输出，一律不做。

参数如果和你的实际经验冲突，以你的为准——改 `CALIB` 那一节，跑一遍自检，看 12 项还在不在。
